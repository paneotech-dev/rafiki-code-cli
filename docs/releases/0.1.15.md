# rafikicode 0.1.15

Release 0.1.15 makes long sessions cheaper: more of each request is read from the provider's cache, at a small share of the full input price. Every item below is in [CHANGELOG.md](../../CHANGELOG.md) with its detail.

Update:

```bash
rafikicode update
```

Then quit any open window and start it again; `rafikicode --continue` reopens your last conversation.

New install:

```bash
curl -fsSL https://get.rafikiai.io | bash
```

On Windows, in PowerShell (then use Windows Terminal):

```powershell
irm https://github.com/paneotech-dev/rafiki-code-cli/releases/latest/download/install.ps1 | iex
```

## Lower cost on long sessions

- **Compacting reads from the cache.** On Rafiki Fast and Rafiki Pro the summary of a long session is asked for at the end of the conversation itself, with the same start as the step before it, so the provider reads almost all of it from its cache instead of a pasted copy of the conversation sent at the full price. A short conversation, Rafiki Max and a configured `compaction` agent keep the pasted copy.
- **Old tool output is replaced only near the compaction point.** Replacing it early made the next request cost more than the replacement saved. The last test run and the newest read of each file you are editing are always kept.

## Tests

The `packages/opencode` session, rafiki, provider and brand suites run on the release commit, with new tests that compare the summary request with the step before it byte for byte. The build was measured against 0.1.14 on five tasks of the release set on Rafiki Fast and three on Rafiki Pro: the same tasks pass, and the tokens per task are in the release report.
