# rafikicode 0.1.10

Release 0.1.10 is the first full release since 0.1.9. It gathers the work of eight pre-releases (0.1.10-rc.1 to rc.8) and changes how `rafikicode` installs, starts, signs in, measures and checks its work. Every item below is in [CHANGELOG.md](../../CHANGELOG.md) with its detail.

Install or update:

```bash
curl -fsSL https://get.rafikiai.io | bash
```

On Windows, in PowerShell (then use Windows Terminal):

```powershell
irm https://github.com/paneotech-dev/rafiki-code-cli/releases/latest/download/install.ps1 | iex
```

On a machine that already has `rafikicode`, run `rafikicode update`.

npm, Homebrew and winget may stay on 0.1.9 for a while after this release. If `rafikicode --version` still shows 0.1.9 after an update through one of them, use the installer line above.

## Installing and starting

- **Installers that repair what they meet.** A full, read-only or noexec temporary folder, a missing `curl`, `tar` or `unzip`, a proxy, a rate limited GitHub API, an older copy earlier on PATH, an install folder that cannot run programs: the installer falls back by itself and prints one line for each fix. It ends with a check of the program in a new login shell and of the gateway, and writes `~/.rafikicode/install.log` when something is still wrong.
- **Shared hosts.** On cPanel style hosts (jailshell) and in shells whose startup file returns early when not interactive, the PATH and TMPDIR lines go where a login shell reads them, and `rafikicode uninstall` removes them again.
- **A folder doctor at start.** An unset home, a full temporary folder, a broken config or data folder, a nearly full disk: `rafikicode` fixes what it can before anything else, and `rafikicode doctor` lists the checks.
- **No more silent start.** In the old Windows console the interface says to open Windows Terminal. Started in the home folder or another folder that is not a project, it works in `~/RafikiCode`.
- **Update channels.** `rafikicode update --pre` follows pre-releases; a copy installed from a pre-release keeps following them.

## Signing in and tiers

- **Rafiki Max for everyone**, at 15x credits, asked once before a session switches to it. When a key lacks Max, the interface offers to sign in again on the spot.
- **Clearer sign-in.** An account still waiting for approval is told so at once.

## What the terminal shows

- **Real figures.** Tokens, the share of the window of the tier that answered, cached tokens, the key's spend and budget and the credits left come from the gateway and the Rafiki AI console, not from a price list. A stopped or failed run still prints its cost, marked partial.
- **History in the sidebar.** Your latest conversations in every folder and the folders you worked in, with `ctrl+x o` for the full list.

## Working on a project

- **Project memory** in `.rafiki/memory/`, read at the start of a session and updated before it ends. `/memory` shows it.
- **Checks after a change.** A turn that changed files runs the project's own tests or build before it is called done, and says plainly when they fail.
- **Long sessions send less.** Old large tool outputs are replaced by a one line note; a session is compacted only near the end of its window.
- **Retry when the model only reasoned.** A turn that used its whole output budget on reasoning is tried again once with more room.
- **GitHub.** `/github` and `rafikicode github` put a project on GitHub step by step, after a scan for secrets. Pushing code always asks first.
- **Works offline better.** Code search falls back to a built-in search when its search tool cannot be downloaded, and a headless run contacts only the Rafiki gateway and console.

## Tests

The full `packages/opencode` suite on the release commit: 4,475 tests pass. The two failures are known and only occur when the suite runs as root. The installer suites, the container suite (Debian, Ubuntu, Alpine, Fedora, cPanel jailshell) and the release gate on all thirteen builds run before anything is published.
