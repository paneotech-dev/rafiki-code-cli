# rafikicode 0.1.4

Release 0.1.4 follows 0.1.1. There is no 0.1.2 or 0.1.3 release: their changes are included here.

Install or update:

```bash
curl -fsSL https://get.rafikiai.io | bash
```

or, on a machine that already has `rafikicode`, run `rafikicode update`.

## Security

- **The local server always requires a password.** `rafikicode serve`, `rafikicode web` and `rafikicode acp` run a local HTTP server that can read files and run commands as you. It now always requires a password.
  - `rafikicode acp` makes a random password for its own process. Editors need no change.
  - `rafikicode serve` and `rafikicode web` on `127.0.0.1`, `::1` or `localhost` make a random password for that server when you have not set one. They store it in `~/.rafikicode/servers/<port>.json` (mode 0600, in a folder with mode 0700) and remove the file when the server exits. The server prints the file name, never the password. `rafikicode attach` and `rafikicode run --attach` on the same machine read the password from that file when it is yours and private and its server is running.
  - A generated password is taken out of the server's environment once it listens, so commands and tools it starts do not inherit it.
  - Any other listen address still needs a password you choose, or the server stops with exit code 2.
  - See [Server files](../configuration.md#server-files).
- **Password variables.** `RAFIKICODE_SERVER_PASSWORD` sets the password and `RAFIKICODE_SERVER_USERNAME` sets the user name (default `rafikicode`). The earlier names `OPENCODE_SERVER_PASSWORD` and `OPENCODE_SERVER_USERNAME` still work when the `RAFIKICODE_` variable is not set. A password you set is used as before, and no server file is written.

## Behaviour changes

- **Scripts that call a local `rafikicode serve` or `rafikicode web` without a password now get `401 Unauthorized`.** Set `RAFIKICODE_SERVER_PASSWORD` for both the server and the script, or read the password from the server file, for example `curl -u "rafikicode:$(jq -r .password ~/.rafikicode/servers/4096.json)" http://127.0.0.1:4096/doc`.
- **Rafiki tiers only.** `rafikicode` offers the Rafiki tiers and nothing else, even when keys for other providers are set in the environment.
  - `enabled_providers`, and model settings that name another provider, are ignored with a warning.
  - `run -m` with a model outside the Rafiki tiers stops with exit code 2.
  - The `providers` command and its alias `auth` were removed and exit with code 2.
- **No key, clear stop.** Without a sign in or `RAFIKICODE_API_KEY`, `rafikicode run` and the terminal interface stop at once with the sign in instructions and exit code 2. `rafikicode acp` still starts, so the editor can offer its sign in action, and answers the ACP error `auth_required` until you sign in.
- **Editor sign in method.** The ACP sign in method is now `rafikicode-login`. The earlier id `opencode-login` is still accepted.

## New

- **`rafikicode login --surface ide`.** Marks a sign in as coming from an editor, so the key list in the Rafiki AI console shows where the key is used. The values are `cli` (the default) and `ide`. Any other value stops with exit code 2 before anything is sent. The editor sign in action runs this command by the full path of the `rafikicode` binary, so it works when the editor's `PATH` lacks `~/.rafikicode/bin`.
- **`doctor` warns about keys not made for Rafiki Code.** A general key from the Rafiki AI console, created without the Rafiki Code option, now gives a `WARN` on the `key` line: runs still work, but Rafiki Code tracks usage only on keys created for it. Create a key with the Rafiki Code option ticked, or run `rafikicode login`. `doctor` still exits 0.
- **`doctor` warns instead of failing for a key the console does not know.** When the gateway accepts a key that the Rafiki AI console does not know, the `console` line is `WARN` with an explanation, and `doctor` exits 0 (it exited 1 before).

## Fixes

- **`rafikicode run --attach` prints the answer again.** It printed nothing and exited 0. A missing or wrong server password now stops it with `The rafikicode server at <url> needs a password` or `... refused the password` and exit code 2, instead of `Session not found`. An address where no server answers gives exit code 4.
- **Editor traffic is labelled.** Model calls from `rafikicode acp` carry the surface `ide`, so editor spend can be told apart from terminal spend.
- **User agent.** Model calls send the user agent `rafikicode/<version>`.
- **Configuration schema address.** New configuration files point at the schema of the installed release. The first command you run replaces the address written by 0.1.0 and 0.1.1, which answered 404, and changes nothing else in the file.
- The upstream `customize-opencode` skill, which described upstream configuration files, is no longer offered, so it no longer appears in the editor's command list.

## Integrity

Release archives are not code signed. The installer and `rafikicode update` check each archive against the published `SHA256SUMS`.
