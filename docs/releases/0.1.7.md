# rafikicode 0.1.7

Release 0.1.7 follows 0.1.6. It adds one command group, `rafikicode gh`, and otherwise finishes the installer work of 0.1.5 and 0.1.6: the installer now signs you in, checks that what it installed runs, and tells the truth about your `PATH`, and `uninstall` removes the link it left behind. Messages that still named the upstream project were rewritten. Existing commands, options, exit codes, the local server and sign in behave as in 0.1.6.

Install or update:

```bash
curl -fsSL https://get.rafikiai.io | bash
```

or, on a machine that already has `rafikicode`, run `rafikicode update`.

## New: GitHub from the command line

`rafikicode gh` creates branches, commits, pushes, opens pull requests, and reads and comments on issues. See [GitHub from the command line](../github.md).

```bash
rafikicode gh branch fix/login-redirect
rafikicode gh commit -m "fix: send the login redirect to the requested page"
rafikicode gh push
rafikicode gh pr create --title "Fix the login redirect" --body "Closes #42"
```

- The subcommands are `status`, `branch`, `commit`, `push`, `pr create`, `pr comment`, `issue list`, `issue view` and `issue comment`.
- No GitHub credential is stored. Every command runs the `git` and `gh` binaries already on your machine and uses the account `gh` is logged in to. Nothing is written to `~/.rafikicode`, so there is no GitHub token here to leak, expire or rotate, and `gh auth logout` revokes access in one place.
- `branch`, `commit` and `push` need a git repository and use `git` alone, so they work whether or not `gh` is installed. The pull request and issue subcommands need `gh` logged in, and stop with a message naming `gh auth login` when it is missing or logged out. `rafikicode gh status` reports the repository, the branch and the state of `gh`, including the absence of either, rather than failing.
- Titles, bodies and commit messages reach `git` and `gh` as single arguments with no shell, so quotes, newlines and shell punctuation in them stay text.

## Behaviour changes

- **The installer signs you in.** It used to end by asking you to run `rafikicode login`. It now starts that sign in itself. `login` prints a short code and a link and then polls, so no browser is needed on the machine you installed to: approve from a laptop or a phone. It runs only when a terminal can be opened for you to type into, only outside CI, and never when `RAFIKICODE_API_KEY` is already set, so a Dockerfile or a provisioning script is unaffected. `--no-login` turns it off. A sign in you decline or that fails does not fail the install: the written instructions follow as before.
- **The installer checks that what it installed runs.** After writing the binary it runs `--version` once. A build for another machine, one built against a newer C library, or one macOS has quarantined used to be reported as a successful install, and you met the failure later as an opaque error from your first real command. The install now stops there, names the exit status and what the binary said, lists those three causes, and leaves the file in place for you to look at.
- **`uninstall` removes the link on your `PATH`.** 0.1.5 taught the installer to link the binary from a directory already on your `PATH`. `uninstall` did not remove that link, so the bare name went on resolving to a binary that was gone and your shell answered with an obscure error from the operating system instead of `command not found`. It is now removed, and named as it goes. A name that is no longer a link to the binary being removed is left alone, and `uninstall` says so, because a regular file or somebody else's link at that name belongs to whoever put it there.
- **`upgrade` and `uninstall` refuse Homebrew, Chocolatey and Scoop.** `rafikicode` is published through its installer and through npm, pnpm, bun and yarn. The commands for the other three were built from the upstream package name, so upgrading or uninstalling through them would have acted on a different product. They now stop and name the installer instead.

## Messages

- The terminal interface headline on a crash reads `Rafiki Code crashed`, and the bug report it opens records the version under a Rafiki Code field.
- An MCP server that fails now suggests what to do, naming `rafikicode mcp auth <name>` for the server that failed. The earlier message said authentication was unsupported, which has not been so for some time. The toast and the `/status` dialog name `rafikicode mcp auth` as well.
- A configuration file with a `permissions` key is answered with `Unsupported key "permissions". Use "permission" for access rules.`, which says what to type instead of naming other products.
- A remote configuration address that answers with a sign in page asks you to supply credentials for it, or to point `config` at an address that needs none, rather than naming a command that does not apply.

Scripts that match the earlier message text need the new wording. Exit codes are unchanged.

## Fixes

- **The `PATH` advice after an install is true in every case.** The next steps promised that new terminals would find `rafikicode` on their own whenever no link could be made. With `--no-modify-path` nothing is written to a startup file at all, so no terminal would have found it. The three outcomes are now told apart: a link was made and the bare name works everywhere; no link, but the entry is in a startup file, so new terminals are set and this one needs the `export`; and nothing written, where the installer says so and asks you to place the line yourself.
- **The installer is served from one address.** `install.sh` ships as a release asset, so `releases/latest/download/install.sh` always serves the installer of the newest release and get.rafikiai.io needs no repointing by hand. This shipped in 0.1.6 and is recorded here because 0.1.6 carried no notes of its own.

## Documentation

- [GitHub from the command line](../github.md) is new, and says for each subcommand whether `gh` has to be logged in.
- The README, the [quick start](../quickstart.md) and the [troubleshooting](../troubleshooting.md) page show what the installer actually prints in each of the three `PATH` outcomes, and treat the `export` line as a fallback rather than a step everyone runs. The quick start notes that its install output is the 0.1.5 installer's and was not run again in containers.
- The troubleshooting entry about a command that still answers after `uninstall` describes the link being removed, and what it means when `uninstall` reports leaving one alone.
- `install/test-install.sh` grew from 8 checks to 16, covering the link, the three `PATH` outcomes, and an installed binary that cannot run.

## Integrity

Release archives are not code signed. The installer and `rafikicode update` check each archive against the published `SHA256SUMS`.
