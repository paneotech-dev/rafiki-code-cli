# rafikicode 0.1.12

Release 0.1.12 makes long sessions much cheaper and keeps them working under the gateway's new limit of 200,000 input tokens per request. It also sends easy work to Rafiki Fast and hard turns to Rafiki Pro on its own, and fixes a silent exit on hosts with a locked temporary folder. Every item below is in [CHANGELOG.md](../../CHANGELOG.md) with its detail.

Update:

```bash
rafikicode update
```

Then quit any open window and start it again; `rafikicode --continue` reopens your last conversation.

New install:

```bash
curl -fsSL https://get.rafikiai.io | bash
```

On Windows, in PowerShell (then use Windows Terminal):

```powershell
irm https://github.com/paneotech-dev/rafiki-code-cli/releases/latest/download/install.ps1 | iex
```

## Long sessions cost much less

- **Compacted at 150,000 tokens.** A session on any tier is summarised once its context reaches 150,000 tokens, instead of near the end of the 1M window. Before, every turn of a long session resent hundreds of thousands of tokens. `compaction.threshold` or `RAFIKICODE_COMPACT_AT` moves the point.
- **Old tool output goes sooner.** The newest 20,000 tokens of tool output stay in full (it was 40,000); older large outputs are replaced with a one line note.
- **Large tool results are not carried around.** A result over about 8,000 tokens is saved to a file in the session's folder. The agent gets its start and its end, how many lines and bytes it has, and the path, and reads the rest by range when it needs it. Command output keeps its first lines as well as its last, and the end of a long output is no longer lost.
- **The start of every request stays the same,** so the provider's cache keeps working: `AGENTS.md` and the project instructions are read once per session, and an edit is used after the next compaction.
- A request over 200,000 tokens shows one line suggesting `/compact` or a new session.

## The gateway's limit of 200,000 input tokens

- **Sessions stay under it.** The tiers know the limit, so a session is compacted before it gets there whatever the settings say.
- **A refusal is not an error.** When the gateway still refuses a request as too large, the session is compacted and the message sent once more, with one line saying so; `rafikicode run` exits 0 when that works.
- **A message too large on its own** stops with one plain message after one compaction, instead of compacting again and again.
- **Very long sessions can always be compacted:** the compaction request is cut to fit under the limit.

## The right tier for the task

- **When you have not chosen a tier,** explore helpers, session titles and summaries run on Rafiki Fast.
- **Hard turns move to Rafiki Pro:** `/deep` (or `rafikicode run --deep`), plan mode on a wide change, the same check failing twice in a row, or the review step. Never because the conversation is long, and never to Rafiki Max. On a large conversation the session is compacted first, and the next turn goes back to your tier.
- With `--model`, a `model` in your configuration or a tier picked in the interface, your tier is kept, except a turn you send with `/deep`.
- `rafikicode run --format json` shows the tier and the reason on each step. `RAFIKICODE_ROUTING=off` turns it off.
- **Rafiki Pro offers reasoning effort variants** (`none`, `low`, `medium`, `high`) like the other tiers, now that it is served by DeepSeek V4 Pro.

## Fixes

- `rafikicode` no longer exits without a word when the temporary folder does not allow running programs (shared hosting). When the system stops it, one line says why.
- The installers end with the line to type when the terminal cannot find `rafikicode` yet.
- A retry is no longer started because an error message happens to contain digits such as 429 or 503 inside a token count.

## Tests

The full `packages/opencode` suite and the interface suite run on the release commit, and the release gate installs, starts, signs in and runs a task on all thirteen builds before anything is published.
