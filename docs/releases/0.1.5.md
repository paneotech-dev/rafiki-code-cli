# rafikicode 0.1.5

Release 0.1.5 follows 0.1.4. It changes what the installer does after it installs, and otherwise changes messages and model lists only: commands, options, exit codes, the local server and sign in behave as in 0.1.4.

Install or update:

```bash
curl -fsSL https://get.rafikiai.io | bash
```

or, on a machine that already has `rafikicode`, run `rafikicode update`.

## Behaviour changes

- **Model lists offer `rafiki-fast` and `rafiki-pro`.** `rafikicode models`, the model picker of the terminal interface (`/models`) and the model list an editor shows over ACP offer these two tiers. A model you set yourself, in `model` in your configuration or with `--model`, keeps working as before, and stays shown as the current model in the picker and in the editor.
- **`doctor` checks the offered tiers.** The `tiers` line lists `rafiki-fast` and `rafiki-pro` when your key allows them, and names only those two when one is missing from the key.

## Messages

Every message now names your Rafiki AI account and the Rafiki AI console (console.rafikiai.io), and speaks of credits.

- Without a key, `run`, the terminal interface and `acp` print:

  ```text
  Rafiki Code needs a Rafiki AI account. Create one in the Rafiki AI console (https://console.rafikiai.io), then run: rafikicode login
  On a server or in CI, create an API key at https://console.rafikiai.io/keys with the Rafiki Code option ticked, and set RAFIKICODE_API_KEY.
  ```

- `rafikicode whoami` shows the balance as `Credits: <amount> USD available`, and the `console` line of `doctor` ends with `credits <amount> USD available`.
- `doctor` explains a key that the Rafiki AI console does not know with `This key is valid at the gateway but not registered in the Rafiki AI console (it was created outside the console).`
- `login`, `logout`, `whoami` and `doctor` name the Rafiki AI console in their progress lines and errors, for example `Could not reach the Rafiki AI console to ...`.
- With `CI` set and only a browser sign in stored, the warning asks for an API key created with the Rafiki Code option.
- The terminal interface asks you to run `rafikicode login` to use the credits of your Rafiki AI account.

Scripts that match the earlier message text need the new wording. Exit codes are unchanged.

## Fixes

- **`rafikicode` works in the terminal that installed it.** The installer writes a
  `PATH` line to your shell's startup file, but a startup file is read by *new*
  shells, so the shell you ran the installer in could not find the program:
  `rafikicode login` answered `command not found` immediately after a successful
  install. The installer now also links the program from a directory that is
  already on your `PATH`, which takes effect in the shell you are already in.
  Only directories that are themselves on `PATH` and writable are used, so this
  does not widen where your shell looks for programs, and a file that is not one
  of the installer's own links is never replaced. Where no such directory exists
  — an unprivileged install, or `--no-modify-path` — the startup file is still
  written for new terminals and the next step now prints the program's full path,
  so the command shown works either way.
- **An upgrade reads as one.** Installing over an existing copy printed
  `Installed version: 0.1.0-rc7` and then `Installing rafikicode version 0.1.5`
  as two unrelated facts; it now names both versions in one line.
- **Configuration schema address.** Builds that are not a release (for example a local build) write the schema address of release 0.1.4, which carries both schema files. Release builds keep the address of their own release.

## Integrity

Release archives are not code signed. The installer and `rafikicode update` check each archive against the published `SHA256SUMS`.
