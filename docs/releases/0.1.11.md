# rafikicode 0.1.11

Release 0.1.11 makes `rafikicode` easier to leave working on its own, shows more of what it is doing, and removes two ways a long session could get stuck. Every item below is in [CHANGELOG.md](../../CHANGELOG.md) with its detail.

Update:

```bash
rafikicode update
```

Then quit any open window and start it again; `rafikicode --continue` reopens your last conversation, and older conversations open with the new panel too.

New install:

```bash
curl -fsSL https://get.rafikiai.io | bash
```

On Windows, in PowerShell (then use Windows Terminal):

```powershell
irm https://github.com/paneotech-dev/rafiki-code-cli/releases/latest/download/install.ps1 | iex
```

## Permission modes

- **Shift+Tab switches between Ask, Auto and Plan.** The status row shows the mode. Ask works as before. Auto runs without questions but still stops for actions that can do real harm: recursive deletes, writing outside the project, system files and `sudo`, rewriting git history, piping a download into a shell, credential files, publishing packages, stopping processes it did not start, and pushing code. Plan is read-only and proposes changes instead of making them.
- **Commands the rules cannot judge** get a quick risk check on Rafiki Fast; when it is unsure, you are asked.
- The choice is kept per project. `rafikicode run --auto` uses the same guards and refuses the guarded actions instead of asking.

## The panel

- **Rafiki Code by PANEOTECH** heads the panel, with the folder and branch under it.
- **A short description of the project** at the top, read from the project memory, AGENTS.md or the README.
- **Agents:** the helpers working for you, with their state, time, and progress from their own task list or their current step.
- **The task list sits higher and stays current,** including the task list of a helper while it works. It no longer shows the tasks a session started with after they changed.

## While a task runs

- **Send a queued message now:** Enter on an empty prompt, or Ctrl+X then Enter. The running step stops at the next safe point (never in the middle of a command or a file write), keeps what it has done, and your message goes next.

## Fewer ways to get stuck

- **No more endless "too many requests".** A long session could send one request larger than the key's tokens-per-minute limit, so every retry was refused. `rafikicode` now reads the key's limit, compacts the session before such a request, and when the gateway still refuses for that reason it compacts and tries once more. `rafikicode doctor` shows the key's limits.
- **Signed out?** Starting `rafikicode` at a terminal signs you in, instead of showing an error.
- **Updates that do not hide.** `rafikicode update` checks which copy a new terminal will run and names an older copy that would hide the update, with the command to remove it. On npm, Homebrew and winget it says plainly when that channel is behind and gives the installer line, instead of reporting an upgrade that did not happen.

## Smaller changes

- Internal and staff accounts show "Credits: not enforced (internal account)" instead of a falling balance; customers keep seeing their real balance.
- `rafikicode run --format json` reports usage on every step and a real cost or "unknown", never a cost of 0, and ends with a task event carrying the key's real spend.

## Tests

The full `packages/opencode` suite and the interface suite run on the release commit, and the release gate installs, starts, signs in and runs a task on all thirteen builds before anything is published.
