# Changelog

- Acceptance criteria and a review before a task is done: at the start of a task that is not trivial, 3 to 5 checkable criteria are written from the request (one short request to Rafiki Fast) and shown at the top of the todo list. A bug report is reproduced first: a test that fails because of the bug (a short script without a test setup), then the fix, then the test passes and is kept. Before the task is reported as done, a review on Rafiki Pro sees only the request, the criteria, the diff, the check results and the last commands, and answers pass or fail per criterion; criteria not met go back to the agent for one more round. The answer ends with a line giving the result and the review's cost. `review.enabled`, `review.rounds`, `review.model` and `RAFIKICODE_REVIEW` configure it; trivial requests and documentation-only changes are not reviewed. See `docs/configuration.md`.
- Requests go to a tier by task when you have not chosen one. Explore subagents, session titles and compaction summaries run on Rafiki Fast. A turn moves to Rafiki Pro only when it is hard: `/deep` or `rafikicode run --deep`, plan mode on a wide change, the same check failing twice in a row, or the review step; never because the conversation is long, and never to Rafiki Max. On a conversation over about 60,000 tokens the session is compacted first, and the next turn goes back to the session's tier. With `--model`, a `model` in the configuration or a tier picked in the interface, every request keeps that tier except a `/deep` turn. The choice and its reason are in the debug log and on the `step_start` and `step_finish` events of `--format json` (`tier`, `route`). `RAFIKICODE_ROUTING=off` turns it off. See `docs/configuration.md`.
- Rafiki Pro now offers the reasoning effort variants `none`, `low`, `medium` and `high`, like Rafiki Fast and Rafiki Max, since it is served by DeepSeek V4 Pro (`--variant`, or ctrl+t in the terminal interface). A Pro turn that runs out of output while reasoning is tried again with less reasoning, as on the other tiers.
- Fix long sessions on the gateway's new limit of 200,000 input tokens per request. The tiers now register that limit, so a session is compacted before it reaches it (at 150,000 tokens by default; a `compaction.threshold` above the limit can no longer push a session past it). When the gateway still refuses a request as too large, the session is compacted and the message is sent once more without an error line, and `rafikicode run` exits 0 when that works. A message that is too large on its own, even after compacting, now stops with one plain message instead of compacting again. The compaction request itself is cut to fit under the limit, so a very long session no longer stops with "Conversation history too large to compact". A retry is no longer started because a refusal's text happens to contain digits such as 429 or 503 inside a token count.
- A large tool result no longer goes whole into every later request. A result over 32 KB (about 8,000 tokens) or 2,000 lines is saved to a file in the session's folder, and the agent gets its start and its end, the line and byte count of the whole, the lines left out and the path, so it can read the rest by range or search it. Command output keeps its first lines as well as its last, and the end of a long output is no longer lost when the command exits while it is still being read. Reading a file gives at most 32 KB per call. `AGENTS.md` and the other project instructions are read once per session, so an edit during the session no longer makes the next request resend the whole conversation at the full price; the edit is used after the next compaction. `tool_output.max_bytes` and `tool_output.max_lines` move the cap. See `docs/configuration.md`.
- Fix `rafikicode` exiting without a word on hosts whose temporary folder does not allow running programs (`/tmp` mounted noexec, common on shared hosting). The folder is checked by running a small file there, and another one is used before the interface starts. When the system ends the restarted interface (for example over a memory limit), one line says why and the exit code is 137, instead of nothing. The installers end with the line to type when the current terminal cannot find `rafikicode` yet (`source ~/.bashrc`), and `install.ps1` refreshes PATH in the PowerShell window it runs in.
- Long sessions cost much less: a session on any Rafiki tier is now compacted once its context reaches 150,000 tokens, instead of near the end of the 1M window (about 936,000 tokens on Rafiki Fast, 968,000 on Rafiki Pro and Rafiki Max), which made every turn of a long session resend hundreds of thousands of tokens. The check runs before each request on the size it would have, so the request over the point is not sent; the session is compacted first. `compaction.threshold` in the configuration and `RAFIKICODE_COMPACT_AT` move the point (`off` keeps only the window). The context share still reads against the real 1M window. Old tool output is pruned harder: the newest 20,000 tokens of tool output stay in full, down from 40,000; the rest of the rule is unchanged. A single request over 200,000 tokens shows one line in the interface and in `rafikicode run` suggesting `/compact` or a new session (`compaction.warn_at`, `RAFIKICODE_WARN_AT`, `0` turns it off). See `docs/configuration.md` and `docs/cost.md`.
- Fix `rafikicode run --format json` reporting a cost of 0 for every request: each `step_finish` event now carries the request's `usage` (input, output, reasoning, cached tokens read and written) and a `cost` that is the gateway's own figure when its answer carries one (`cost_source: "gateway"`), or `null` with `cost_source: "unknown"`, never 0. A last `task` event gives the key's spend difference read from the gateway before and after the task, the figure of the `Task:` line. See `docs/headless-and-ci.md`.
- Fix `rafikicode update` on npm, Homebrew and winget when they lag behind the GitHub release. It printed `Upgrade complete` after a `brew upgrade` that changed nothing, and asked winget for a version winget did not have, failing with a bare exit code. It now asks the package manager which version it offers (`npm view`, `brew info`, `winget show`): when that is behind the latest release, it says so plainly and gives the installer line (`curl` or PowerShell) that installs the newer version. After any upgrade it runs `rafikicode --version` on the updated copy and prints `Upgrade complete` only when the version changed; otherwise it says nothing was upgraded and exits with code 1. The daily check gives the installer line instead of a package manager command that would find nothing.
- Fix an older copy earlier on PATH hiding an update. After installing, `rafikicode update` asks a new shell which `rafikicode` it runs (`command -v`, or `Get-Command` with the PATH a new Windows terminal gets); when that is another file, it names it with its version and gives the command that removes it, or the line that puts the updated copy first on PATH. `rafikicode doctor` shows the same check on a `new shell` line, and its `path` line now gives the removal command too (`npm uninstall -g`, `brew uninstall`, `winget uninstall` or `rm`, as the installer does).
- Terminal interface: a queued message can be sent now (Enter again on the empty prompt, `ctrl+x` then Enter, "Send queued message now" in the command list, or "Send now" on the queued message, which shows how). The running turn stops after the tool call in progress, never during one, keeps its work and takes the message next. The sidebar starts with two sentences about the project (from `.rafiki/memory/project.md`, else `AGENTS.md` or `README.md`, read from the files and updated when they change), then an `Agents` section listing the subagents of the conversation with their state, time and progress (the share of their todo list that is done, or their steps; a click opens one), then the todo list, now under them. Fix the todo list staying on an old list: a todo update that arrived while a conversation was being loaded was replaced by the list as it was when loading started, and the list of a running subagent was never shown. The footer reads `Rafiki Code by PANEOTECH`, with the folder and the version under it. Conversations started with earlier versions show all of it too.
- Signed out, `rafikicode` and `rafikicode run` at a terminal now say `Not signed in. Starting sign-in.`, run the same browser sign-in as `rafikicode login` and carry on once it is approved, instead of stopping with an error. Ctrl+C stops it; a refused or expired sign-in shows the reason and the usual message. Without a terminal, in CI, with `--format json` or with `RAFIKICODE_NO_AUTO_LOGIN=1`, the message and exit code 2 are as before. `rafikicode logout` ends with how to sign in again.
- Permission modes: Ask (as before), Auto and Plan, cycled with Shift+Tab in the terminal interface and shown in the status row and the footer. The pick is kept per project on your machine (`~/.local/state/rafikicode/permission-mode.json`), never in the project; `permission.mode` and `RAFIKICODE_PERMISSION_MODE` set the default. Auto mode runs tool calls without a question except guarded actions, which still ask every time: publishing code, recursive deletes, deletes and writes outside the project and temp folders, system paths, `sudo`, `su` and `doas`, git history rewrites (`push --force`, `reset --hard`, `filter-branch`, `branch -D` of the default branch), a download piped into a shell, credential files (`~/.ssh`, `~/.aws`, `.env` outside the project, the sign-in file), a tool that sends email, package publishing and stopping processes the session did not start. They are found by rules that read compound commands, `sh -c` and `eval` strings, env prefixes, wrappers and git aliases; a command the rules cannot classify gets a risk check on `rafiki-fast` (`{"risk": "low" | "high"}`, 5 seconds, kept per command for the session, off with `permission.auto_check: false`). Plan mode is read-only: edits and commands that change things are refused with a note and the agent proposes instead. A `"deny"` rule always wins, and a rule written for a guarded command by name lets it run. `rafikicode run --auto` is auto mode with the same guards: a guarded action is refused with the reason and how to allow it. An untrusted workspace cannot turn auto mode on. Shift+Tab no longer selects the previous agent (`agent_cycle_reverse` has no key by default). In the interface's auto mode, a push no longer goes through without its question.

- Release workflow: a full release needs only the repository secret `RAFIKICODE_STAGING_API_KEY`, which runs the live sign-in and task checks of the gate. `NPM_TOKEN`, `HOMEBREW_TAP_TOKEN` and `WINGET_TOKEN` are optional: without one, the preflight job writes a warning naming it and that channel is skipped, not failed, while the GitHub release, `install.sh`, `install.ps1` and `get.rafikiai.io` are published as before. The run summary and a "Package managers" section of the release notes say which channels were published and which were skipped. Until their tokens are set, npm, Homebrew and winget may lag behind the GitHub release; the installer script always has the latest release. Maintainer steps are in `docs/releasing.md`.
- Update channels: `rafikicode update --pre` (or `--prerelease`) installs the newest release including pre-releases, read from the GitHub releases list (the release page when the API is rate limited) and compared by semantic versioning. The `channel` setting (`"stable"` or `"pre"`) and `RAFIKICODE_UPDATE_CHANNEL` choose what the daily check and `rafikicode update` follow; a copy installed from a pre-release follows pre-releases by default. On `stable`, `rafikicode update` says in one line when a newer pre-release exists, with the command. npm, Homebrew and winget have stable releases only, and say so with the installer line to use instead. A pre-release copy on `stable` is no longer taken back to an older release.
- Rafiki Max missing on the key: the terminal interface now offers "Sign in again now" (or `y`) in that dialog, shows the address and the code, opens the browser when it can, stores the new key in place of the old one and retries the switch to Rafiki Max. `rafikicode run` and the gateway's refusal name the one command, `rafikicode login`, which now starts a new sign-in instead of rotating a key that lacks Max.
- Merge upstream `dev` at 1.18.34 (commit a79ecfe109), the first upstream sync since the fork; see docs/plans/upstream-sync.md.
- Install channels and automatic updates: `rafikicode` installs through the installer script, npm, Homebrew and winget from the same release archives, updates itself once a day with a checksum verified background download applied at the next start, ships its licence and notice on every channel, and the release workflow now gates all twelve builds (install, version, licence, staging sign-in, one task) before anything is published.
- Network resilience: a model response cut by a dropped connection is continued from the text or the tool call that had arrived instead of being requested again, connection errors in the middle of a task are retried with backoff and jitter for a window (`RAFIKICODE_RETRY_WINDOW`, default 2 minutes), `rafikicode --resume` reopens the last session and repairs a step left open by a killed process so undo restores its files, and every task request carries an `Idempotency-Key` header (the gateway side is specified in `docs/contracts/idempotency-key.md` and is not implemented yet).
- Requests start with the same bytes from one request of a task to the next (system prompt, project instructions, skills, repository context; the date moved out into a message of its own), and tiers that need one carry a prompt cache marker at the end of that part (`RAFIKICODE_CACHE_MARKERS`), so repeated context can be billed at cache rates.
- Show what a task costs: tier, estimated spend and credits left on the status line, an estimate before a tier change, one line after the task (tier path, estimated spend, cache saving), `rafikicode usage` for the last 30 days by day and by tier, and `X-Rafiki-Tier` and `X-Rafiki-Escalation` on every gateway request.

- Docs: the install page lists every method `rafikicode update --method` takes (`curl`, `npm`, `pnpm`, `bun`, `brew`, `winget`), and the translated README files no longer give the upstream project's install commands: their install section points at `docs/install.md`.
- Fix the interface refusing to start on a terminal that reports 0 columns by 0 rows (`docker run -t` with no terminal on the client side, some CI runners, a terminal that has just been attached): a size of 0 means the size is not known, and the interface now draws at 80 by 24. Standard output that is not a terminal, and a terminal that reports a real size too small to draw in, are refused with the same messages and exit code 7 as before.

- Fix the code signatures of the macOS builds. They are cross compiled on Linux, and the archives carried the signature the compiler left: darwin-arm64 had one wrong page hash (its last page, hashed as if padded with zeros) and darwin-x64 carried the Bun runtime's own Developer ID signature, which covered less than half of the file. The release now signs every macOS build ad hoc once the binary is final, checks every page hash of the archived binaries before anything is published, and checks them again with Apple's `codesign --verify --strict` on the macOS gate runners.

Its check also read the exit code wrongly, so a program that printed a line and then failed passed it. Without `USERPROFILE` (PowerShell outside Windows) it stops with a message naming the shell installer and `-Prefix`, instead of a PowerShell binding error.

Without `RAFIKICODE_STAGING_API_KEY` it is still built, signed and gated, the gate skips only the sign-in and the task against staging (`--no-live` / `-NoLive`, passed explicitly by the workflow and refused for a full release), records them as `skipped (no staging key, pre-release)`, and the release notes say so.

Both installers create the folder and name it in their next steps.
- Folder doctor: before anything else, `rafikicode` fixes the folders it needs, with one line for each fix: an unset or unwritable home folder, a temporary folder that is full, missing or unwritable (`~/.rafikicode/tmp`, with TMPDIR, TEMP and TMP set), and a configuration, data, cache or state folder that is a file or cannot be written. `rafikicode doctor` lists each check and what was done, and `rafikicode doctor --folders` lists only those, with no network.
- Installers fix what they meet by themselves: `wget`, `python3` or `perl` when there is no `curl`; `bsdtar`, `busybox` or `python3` when there is no working `tar` or `unzip`; the direct latest address when the API and the release page refuse; proxies in either case and, on Windows, the system proxy with your sign in; three tries for a download cut short or a checksum that does not match; the clock named on a TLS failure it causes; `~/.rafikicode/tmp` for a full or read only temporary folder; `~/.rafikicode/bin`, then `~/.local/bin`, for an install folder that cannot be written or runs no programs; the home folder from the password database when HOME is unset. They refuse root through sudo into a user's home, name an older copy first on PATH and put the new one first, add the PATH line for bash, zsh and fish, detect antivirus removing the binary on Windows, end with a green or red check (program, gateway, folders), and save `~/.rafikicode/install.log` with the address to send it to when anything fails.
- `install.ps1` run through `irm ... | iex` no longer closes the PowerShell window on an error: it prints the error and returns to the prompt with `$LASTEXITCODE` 1, leaving nothing behind in the session; run as a file it still exits with code 1. The prompt row read `Rafiki Fast Rafiki` and now reads `Rafiki Fast`. The sidebar shows the cached part of the tokens beside the total, and cache writes the gateway reports are counted as cache writes instead of plain input, each token once. When the gateway answers on another tier after a failure, the message footer, the percentage, the tier path and the cost estimate follow the tier that answered, and `rafikicode run` says so. The agent introduces itself as Rafiki Code by PANEOTECH and names its tier instead of another product or company. `RAFIKICODE_MAX_OUTPUT_TOKENS` now goes up to the maximum of each tier's model. Sessions are compacted at the same point as before (64,000 tokens on `rafiki-fast`, 96,000 on `rafiki-pro`).

- Fix `rafikicode --version` and `--help` on a machine whose folders had to be replaced: the folder doctor wrote its line about the fix on standard error there too, and anything that compared the output of `--version` with standard error folded in (the release gate, the install matrix, scripts) read that line instead of the version. For `--version`, `--help` and shell completion it now says nothing unless a folder could not be repaired, and does not start the program a second time. Free space the system reports in a way that cannot be right (a block size of 0, no blocks, more free than the disk holds) is treated as unknown instead of as a full disk. The version check reads standard output only, which must be the version alone on one line; what the program wrote on standard error is reported as a `::warning` annotation. The install matrix reads `--version` the same way, and its record now expects the `tmp-tiny` and `home-unset` machines to pass every check, as they do since the installers fall back by themselves.
- Rafiki Max is offered to everyone: `rafiki-max` is listed in the model dialog of the terminal interface, `rafikicode models`, an editor's model option and `doctor`, each tier with its credit rate (fast 1x, pro 4x, max 15x). The interface asks once before a session moves to Rafiki Max, the cycling shortcuts never move to it before that, and a new session never starts on it unless the configuration or `--model` asks for it; `rafiki-fast` stays the default. When the key in use was approved without Max, picking it in the interface or `rafikicode run --model rafiki/rafiki-max` says so before anything is sent, from the gateway's own answer about the key, and names the fix: run `rafikicode login` again and tick Max. The gateway's refusal of a tier names the same fix.
- Every figure the terminal shows is now read from the gateway or the Rafiki AI console, not estimated from a price list. The `Context` block and the prompt row describe the last request: tokens sent (with the cached part inside), the share of the window of the tier that answered, and tokens received. The new `Spend` block and the prompt row show what the key has spent since the session started, the key's spend and budget with the share used (the gateway's `/key/info`), and the credits left in the account (the console's `/api/v1/me`), read after each completed answer and never while one streams; a failed reading keeps the last figures and marks them stale. `rafikicode run` ends with the requests and tokens of the task and what the key spent during it. The estimated amounts, the "caching saved" figure and the estimate for a turn on another tier are gone; a tier change names the tier and its credit rate instead.
- History in the sidebar: the terminal interface lists your latest conversations in every folder (title, folder, tier, last activity) and the folders you worked in, newest first, in a `History` section of the sidebar and in a full list on `ctrl+x o` (or `History` in the command list). Click or pick one to continue: a conversation of the current folder opens at once, one of another folder or a folder starts the interface again there. The list comes from the sessions the program already keeps, is read only when shown, and never slows the start. Builder projects are not listed, since the builder has no route a Rafiki Code key can list them with.
- Long sessions send less: on the Rafiki tiers, old large tool outputs are replaced by a one line note that names the call and says to run it again, before each turn. The latest turn, the newest 40,000 tokens of tool output, errors, failed commands and file edits are always sent in full, and the conversation is rewritten only when more than 20,000 tokens can go at once, so the prompt cache is rebuilt rarely. `"compaction": {"prune": false}` or `RAFIKICODE_PRUNE=0` turns it off. Compaction still starts near the full window.
- Publishing code asks every time: `git push` in any form, `gh pr create`, `gh repo create`, `gh release` and similar commands ask for your yes in the interface even when shell commands are allowed, with no "Allow always". `rafikicode run` refuses them, `--auto` or not, unless the run allows pushes with `--allow-push`, `RAFIKICODE_ALLOW_PUSH=1` or `{"permission":{"publish":"allow"}}`.
- `/github` in the terminal interface and `rafikicode github` put a project on GitHub step by step: they check `git` and `gh` (and say how to install them and sign in on each system), create the git repository if you agree, scan for secrets and stop when they find one, make the first commit, create a private repository, push, show its address, and offer a pull request and the deploy guide in `docs/github.md`.
- Project memory: each project keeps four short Markdown files in `.rafiki/memory/` (`project.md`, `decisions.md`, `progress.md`, `notes.md`). A session reads them at its start, after the project instructions, with the same bytes on every request so the prompt cache is kept, and the agent records decisions, progress and gotchas before its final answer and after a compaction with a dedicated `memory_update` tool (one section, append, replace or remove); file edits to the folder are refused. Every write is scanned for secrets like `/github` and refused when one is found, the memory stays under 8 KB (`memory.max_bytes`), and nothing is written outside the project folder. `/memory` shows the files and opens one in your editor; in a git repository the memory is suggested for commit, never committed for you. `"memory": {"enabled": false}` or `RAFIKICODE_MEMORY=0` turns it off. See `docs/memory.md`.
- Checks after a change: a turn that changed files is not called done until the project's own checks pass. The checks are found from `package.json` scripts, pytest (or a project's `bin/test`), `go.mod`, `Cargo.toml`, `composer.json` and phpunit, Makefile targets and the commands `AGENTS.md` names, or set with a `Verify` section in `AGENTS.md` or `verify.commands`. The tests of the changed files run first, then type check, lint and build, within 120 seconds (`verify.timeout`); a failure goes back to the agent for up to two fix rounds (`verify.rounds`), and an answer whose checks still fail ends with `checks failing: ...`. `rafikicode run` shows the status on the `Task:` line and in a `verify` JSON event, and exits with code 8 when the checks still fail. A short working practice in the system prompt asks the agent to reproduce a reported bug first, prefer editing over long exploration, and not try to download packages or reference copies. `"verify": {"enabled": false}` or `RAFIKICODE_VERIFY=0` turns it off. See `docs/configuration.md`.
