# Changelog

- Merge upstream `dev` at 1.18.34 (commit a79ecfe109), the first upstream sync since the fork; see docs/plans/upstream-sync.md.
- Install channels and automatic updates: `rafikicode` installs through the installer script, npm, Homebrew and winget from the same release archives, updates itself once a day with a checksum verified background download applied at the next start, ships its licence and notice on every channel, and the release workflow now gates all twelve builds (install, version, licence, staging sign-in, one task) before anything is published.
- Network resilience: a model response cut by a dropped connection is continued from the text or the tool call that had arrived instead of being requested again, connection errors in the middle of a task are retried with backoff and jitter for a window (`RAFIKICODE_RETRY_WINDOW`, default 2 minutes), `rafikicode --resume` reopens the last session and repairs a step left open by a killed process so undo restores its files, and every task request carries an `Idempotency-Key` header (the gateway side is specified in `docs/contracts/idempotency-key.md` and is not implemented yet).
- Requests start with the same bytes from one request of a task to the next (system prompt, project instructions, skills, repository context; the date moved out into a message of its own), and tiers that need one carry a prompt cache marker at the end of that part (`RAFIKICODE_CACHE_MARKERS`), so repeated context can be billed at cache rates.
- Show what a task costs: tier, estimated spend and credits left on the status line, an estimate before a tier change, one line after the task (tier path, estimated spend, cache saving), `rafikicode usage` for the last 30 days by day and by tier, and `X-Rafiki-Tier` and `X-Rafiki-Escalation` on every gateway request.
- Fix the message for a proxy or sign on page answering a model request with 401: it named the upstream project's command and now says `rafikicode login` or `RAFIKICODE_API_KEY`, in the words used for a missing sign in everywhere else.
- Docs: the install page lists every method `rafikicode update --method` takes (`curl`, `npm`, `pnpm`, `bun`, `brew`, `winget`), and the translated README files no longer give the upstream project's install commands: their install section points at `docs/install.md`.
- Fix the interface refusing to start on a terminal that reports 0 columns by 0 rows (`docker run -t` with no terminal on the client side, some CI runners, a terminal that has just been attached): a size of 0 means the size is not known, and the interface now draws at 80 by 24. Standard output that is not a terminal, and a terminal that reports a real size too small to draw in, are refused with the same messages and exit code 7 as before.
- Fix the browser page shown after a provider or MCP sign in: its title, its messages and its wordmark named the upstream product and now say Rafiki Code.
- Fix the name an MCP server shows on its consent screen: `rafikicode` registered for OAuth under the upstream product's name and address and now registers as Rafiki Code with `https://code.rafikiai.io`. Servers already signed in keep their registration.
- Fix the OpenAPI document the local server publishes at `/doc`: its title, descriptions and summaries named the upstream product and now name Rafiki Code and `rafikicode`. Paths, operation ids, tags and schemas are unchanged.
- Fix two errors of the local server's client that named the upstream product: an empty answer and an answer in HTML are now reported as coming from "the server".
- Fix the example in the help of `install.ps1` (`Get-Help .\install.ps1 -Examples`): it gave `https://get.rafikiai.io/install.ps1`, an address that serves the shell installer whatever the path, and now gives the release address the install page gives, `https://github.com/paneotech-dev/rafiki-code-cli/releases/latest/download/install.ps1`.
- Fix the code signatures of the macOS builds. They are cross compiled on Linux, and the archives carried the signature the compiler left: darwin-arm64 had one wrong page hash (its last page, hashed as if padded with zeros) and darwin-x64 carried the Bun runtime's own Developer ID signature, which covered less than half of the file. The release now signs every macOS build ad hoc once the binary is final, checks every page hash of the archived binaries before anything is published, and checks them again with Apple's `codesign --verify --strict` on the macOS gate runners.
- Fix `install.ps1` reporting success when the program it installed does not run: it now exits with code 1 and says so. Its check also read the exit code wrongly, so a program that printed a line and then failed passed it. Without `USERPROFILE` (PowerShell outside Windows) it stops with a message naming the shell installer and `-Prefix`, instead of a PowerShell binding error.
- Docs: the macOS builds need macOS 13 (Ventura) or newer; the macOS and Git Bash routes of the shell installer need `unzip`; Alpine needs `apk add libstdc++ libgcc`; `install.ps1` is fetched from the GitHub release address, since `get.rafikiai.io` serves only `install.sh`.
- Release workflow: a pre-release needs no repository secret. Without `RAFIKICODE_STAGING_API_KEY` it is still built, signed and gated, the gate skips only the sign-in and the task against staging (`--no-live` / `-NoLive`, passed explicitly by the workflow and refused for a full release), records them as `skipped (no staging key, pre-release)`, and the release notes say so. A full release still needs all four secrets.
- Fix `rafikicode` showing nothing in the old Windows console: in `conhost.exe`, which Windows PowerShell and `cmd` open on Windows 10 outside Windows Terminal, or in a console that refuses virtual terminal processing, the interface now says that it cannot draw there, names Windows Terminal (`winget install --id Microsoft.WindowsTerminal`) and `rafikicode run "your task"`, and exits with code 7. Every other command runs as before, `rafikicode doctor` gains a `terminal` line on Windows, and `RAFIKICODE_FORCE_TUI=1` skips the check.
- Fix `rafikicode run` hanging after its first line when started in a large directory that is a git repository: the file checkpoint taken before the first model request is now bounded (10,000 files, 10 seconds) and skipped in the home folder and at a filesystem root.
- Started from a folder that is not a project (the home folder, a drive root, a system folder, Desktop, Downloads, a OneDrive root, or more than 50,000 files outside git), or one that was deleted, cannot be written or does not answer, the interface and `run` work in `~/RafikiCode` instead, created on first use, and say so in one line; a nearly full disk under it gets one warning. `--dir`, the project argument and `RAFIKICODE_NO_DEFAULT_WORKSPACE=1` keep the current directory. Both installers create the folder and name it in their next steps.
- Folder doctor: before anything else, `rafikicode` fixes the folders it needs, with one line for each fix: an unset or unwritable home folder, a temporary folder that is full, missing or unwritable (`~/.rafikicode/tmp`, with TMPDIR, TEMP and TMP set), and a configuration, data, cache or state folder that is a file or cannot be written. `rafikicode doctor` lists each check and what was done, and `rafikicode doctor --folders` lists only those, with no network.
- Installers fix what they meet by themselves: `wget`, `python3` or `perl` when there is no `curl`; `bsdtar`, `busybox` or `python3` when there is no working `tar` or `unzip`; the direct latest address when the API and the release page refuse; proxies in either case and, on Windows, the system proxy with your sign in; three tries for a download cut short or a checksum that does not match; the clock named on a TLS failure it causes; `~/.rafikicode/tmp` for a full or read only temporary folder; `~/.rafikicode/bin`, then `~/.local/bin`, for an install folder that cannot be written or runs no programs; the home folder from the password database when HOME is unset. They refuse root through sudo into a user's home, name an older copy first on PATH and put the new one first, add the PATH line for bash, zsh and fish, detect antivirus removing the binary on Windows, end with a green or red check (program, gateway, folders), and save `~/.rafikicode/install.log` with the address to send it to when anything fails.
- `install.ps1` run through `irm ... | iex` no longer closes the PowerShell window on an error: it prints the error and returns to the prompt with `$LASTEXITCODE` 1, leaving nothing behind in the session; run as a file it still exits with code 1. Its next steps now name `rafikicode login` and `rafikicode doctor`.
- `rafikicode login` for an account still waiting for email verification or approval: after two minutes it says that this may be the cause, the expiry message says so too, and it stops at once when the Rafiki AI console answers `account_pending` (specified in `docs/contracts/device-account-pending.md`, not yet sent by the console).
- Fix what the terminal interface says about the model, the context and the tokens. The context percentage was measured against a 128,000 token window on every tier; it is now measured against the window of the model behind the tier (1,000,000 tokens on each, from the providers' documentation, 4 October 2026), so 24,942 tokens read 2%, not 19%. The prompt row read `Rafiki Fast Rafiki` and now reads `Rafiki Fast`. The sidebar shows the cached part of the tokens beside the total, and cache writes the gateway reports are counted as cache writes instead of plain input, each token once. When the gateway answers on another tier after a failure, the message footer, the percentage, the tier path and the cost estimate follow the tier that answered, and `rafikicode run` says so. The agent introduces itself as Rafiki Code by PANEOTECH and names its tier instead of another product or company. `RAFIKICODE_MAX_OUTPUT_TOKENS` now goes up to the maximum of each tier's model. Sessions are compacted at the same point as before (64,000 tokens on `rafiki-fast`, 96,000 on `rafiki-pro`).
- A long session now uses the whole window of its tier before it is compacted: about 936,000 tokens on `rafiki-fast` and 968,000 on `rafiki-pro` and `rafiki-max`, instead of 64,000 and 96,000.
- Fix `rafikicode --version` and `--help` on a machine whose folders had to be replaced: the folder doctor wrote its line about the fix on standard error there too, and anything that compared the output of `--version` with standard error folded in (the release gate, the install matrix, scripts) read that line instead of the version. For `--version`, `--help` and shell completion it now says nothing unless a folder could not be repaired, and does not start the program a second time. Free space the system reports in a way that cannot be right (a block size of 0, no blocks, more free than the disk holds) is treated as unknown instead of as a full disk. A start folder whose files could not be counted within 2 seconds is no longer moved to `~/RafikiCode`: only a count that reaches 50,000 files moves it, and a folder is treated as not answering after 10 seconds instead of 2. The closing check of `install.sh` gives the gateway 20 seconds (`RAFIKICODE_INSTALL_CHECK_TIMEOUT`) instead of waiting without limit.
- Release gate: a failing check now says why where it can be read without the job log. `install/release-gate.sh` and `install/release-gate.ps1` write one `::error` annotation for each failing check and for a gate that could not start, with the reason (for a failed install, the installer's own error line), and the verdict table, the reasons and the end of the probe log in the job's step summary. The version check reads standard output only, which must be the version alone on one line; what the program wrote on standard error is reported as a `::warning` annotation. The install matrix reads `--version` the same way, and its record now expects the `tmp-tiny` and `home-unset` machines to pass every check, as they do since the installers fall back by themselves.
- Rafiki Max is offered to everyone: `rafiki-max` is listed in the model dialog of the terminal interface, `rafikicode models`, an editor's model option and `doctor`, each tier with its credit rate (fast 1x, pro 4x, max 15x). The interface asks once before a session moves to Rafiki Max, the cycling shortcuts never move to it before that, and a new session never starts on it unless the configuration or `--model` asks for it; `rafiki-fast` stays the default. When the key in use was approved without Max, picking it in the interface or `rafikicode run --model rafiki/rafiki-max` says so before anything is sent, from the gateway's own answer about the key, and names the fix: run `rafikicode login` again and tick Max. The gateway's refusal of a tier names the same fix.
- Every figure the terminal shows is now read from the gateway or the Rafiki AI console, not estimated from a price list. The `Context` block and the prompt row describe the last request: tokens sent (with the cached part inside), the share of the window of the tier that answered, and tokens received. The new `Spend` block and the prompt row show what the key has spent since the session started, the key's spend and budget with the share used (the gateway's `/key/info`), and the credits left in the account (the console's `/api/v1/me`), read after each completed answer and never while one streams; a failed reading keeps the last figures and marks them stale. `rafikicode run` ends with the requests and tokens of the task and what the key spent during it. The estimated amounts, the "caching saved" figure and the estimate for a turn on another tier are gone; a tier change names the tier and its credit rate instead.
